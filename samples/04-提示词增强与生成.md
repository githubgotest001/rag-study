# 提示词增强（Augment）与答案生成（Generate）

## 什么是提示词增强

提示词增强是 RAG 问答阶段的关键一步：把检索到的文本块按照固定模板拼接进提示词（prompt），和用户的问题一起交给大语言模型。一个典型的 RAG 提示词包含四个部分：角色与规则说明（“你是知识库问答助手，只根据资料回答”）、编号列出的资料片段、用户的问题、以及输出要求（“在句末用 [编号] 标注引用”）。

## 为什么要“只根据资料回答”

这条指令是 RAG 抑制幻觉的核心手段。没有这条约束时，模型会混用自己训练时记住的知识和检索资料，一旦两者冲突或资料不足，模型很容易编造内容。加上约束后，模型的行为变成“开卷考试”：资料里有就答，资料里没有就明确说“无法回答”，可靠性大幅提升。同时要求模型标注引用编号，前端就能把每句话对应的原文来源展示出来，用户可以自行核对。

## 引用标注的价值

引用（citation）让 RAG 系统变得可审计。用户看到答案中的 [1]、[2] 标记，点开就能看到对应的原文片段、来源文件和相似度分数。这带来三个好处：用户可以核实答案是否忠于原文；开发者可以诊断“答错是因为检索不准，还是模型理解错了”；在法律、医疗等严肃场景中，可追溯性是系统能否落地的硬性要求。

## 没有大语言模型时怎么办

RAG 的前六个步骤（入库、切块、向量化、索引、检索、增强）完全不依赖大语言模型，只有最后的生成步骤需要。在没有 LLM API Key 的环境里，系统可以退化为“抽取式回答”：把检索到的块进一步拆成句子，用同一个 embedding 模型计算每个句子与问题的相似度，挑出最相关的几句直接拼接成答案，并保留引用标注。这种答案虽然不如 LLM 流畅，但完全忠于原文、零幻觉，也让学习者看清了“检索”与“生成”各自的贡献。本系统正是这样设计的：不配置 OPENAI_API_KEY 时自动走抽取式回答，配置后则调用真正的 LLM 生成。

## 生成参数的小建议

RAG 场景通常把 temperature 调低（如 0.2 以下），让模型输出更稳定、更贴近资料；上下文窗口有限时，优先保证资料片段的完整性，其次才是数量；如果模型经常答“无法回答”，先检查检索环节是否真的召回了相关内容，而不是急着改提示词。
